# Scheduling and non-learning comparators

## Processor scheduling

A task reserves several cores and runs without pre-emption (`_schedule_multi_on_heap` in `envs/vec_env_offload_nrv2x_m_v01_seeded.py`). It reserves `k = min(k_max, cores)` cores, where `k_max` depends on the task class and the executor (`config.py`, `PARALLEL`):

| Class | Parallel fraction `P` | `k_max` vehicle | `k_max` RSU |
|---|---:|---:|---:|
| Safety | 0.60 | 4 | 8 |
| Automated driving | 0.60 | 4 | 8 |
| Infotainment | 0.80 | 6 | 12 |

A vehicle with fewer cores than `k_max` uses all its cores. Because an RSU has eight cores, every RSU task reserves all eight, and each RSU executes at most one task at a time.

Execution time follows Amdahl's law with a parallel-efficiency factor and a per-core overhead:

```
t_k = (cycles / per-core clock) * ((1 - P) + P / (eta * k)) + (k - 1) * delta
```

with `eta = 0.80` on vehicles, `eta = 0.90` on RSUs and `delta = 0.2 ms` per additional core.

The task takes the `k` cores that become free earliest and starts when all `k` are free and its input has arrived. Tasks are placed in the order in which they are committed, so executors serve their queues first-come, first-served in decision order. Tasks run concurrently on an executor only where unreserved cores remain. Every task is executed to completion; deadline misses are recorded but no task is dropped.

## Greedy

Greedy evaluates the valid Local, RSU and V2V alternatives on copies of the executor queues and selects the alternative with the shortest predicted completion time (`greedy_action` in `scripts/evaluate_models.py`).

The estimate includes:

- tasks already committed to the executor;
- multi-core allocation;
- upload delay;
- result-return delay, using the predicted position of the requester at the start of the return transfer;
- predicted processing time.

It excludes:

- other tasks generated in the same traffic frame, because all candidates of a frame are evaluated when the frame begins;
- future task arrivals;
- radio contention.

Greedy uses the simulator's full predicted completion time for each alternative. The DQN observation contains the same queue waits, but only single-clock processing-time estimates and no result-return time (`observation-space.md`). Greedy is therefore an information-advantaged heuristic, not an information-matched deployment baseline.

Greedy evaluates the same preselected peer and RSU presented to DQN.

The Greedy-NoV2V variant (`scripts/eval_greedy_nov2v.py`) applies the same rule with the V2V alternative removed.

## Local

Local assigns every task to its requesting vehicle.

## Random

Random selects uniformly from the valid alternatives presented to DQN-Full. Its choices are generated by a random-number generator seeded with the evaluation seed 7000, so reported results can be reproduced.
